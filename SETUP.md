# Google Ads в терминала - настройка от нула

Този документ те превежда през целия процес: от празна машина до момента, в който пишеш
на Claude Code „покажи ми search terms от миналата седмица с over 20 лв. разход и нула
конверсии" и получаваш отговор от реалния акаунт за 3 секунди.

**Какво получаваш накрая**

- Всичките си Google Ads акаунти под едно MCC, достъпни от терминала, без такса за акаунт.
- Четене: произволна GAQL заявка, одит на акаунт с едно извикване, история на промените.
- Писане: пауза/пускане, бюджети, бидове, ключови думи, негативи, RSA реклами - всяко
  минало през предпазни правила, със снимка на старата стойност и възможност за връщане назад.

**Колко време отнема**

Около 40 минути реална работа. Плюс чакане за одобрение на developer token от Google -
от няколко часа до няколко дни. Затова **част 1 се прави първа**, а останалото върви,
докато чакаш.

**Какво трябва да имаш**

- Manager (MCC) акаунт в Google Ads. Без MCC няма достъп до API Center и няма developer token.
- Google акаунт, който има достъп до това MCC.
- Компютър с права да инсталираш програми.

> **Едно правило над всички:** Google Cloud проектът, съгласието при OAuth и достъпът до
> MCC-то трябва да са на **един и същ Google акаунт**. Най-честата причина настройката да
> се провали е, че някъде по пътя е избран друг акаунт от браузъра. Ако имаш повече от един
> Google профил в браузъра, направи всичко в отделен прозорец, където си влязла само с този.

## Част 0. Предпоставки

### 0.1 Node.js 20 или по-нов

Провери какво имаш:

```bash
node -v
npm -v
```

Ако версията е под 20 или командата не се намира, инсталирай от [nodejs.org](https://nodejs.org)
(вземи LTS) или, на macOS с Homebrew:

```bash
brew install node
```

### 0.2 Claude Code

```bash
claude --version
```

Ако липсва - инсталация и вход:

```bash
npm install -g @anthropic-ai/claude-code
claude
```

При първо пускане те пита за вход в Anthropic акаунта. Нужен е платен план или API
креденшъли.

### 0.3 Ако си на Windows

Скриптовете са писани за Unix среда. Работят най-чисто под **WSL** (Ubuntu) или **Git Bash**.
В обикновен `cmd.exe` пътищата с `~` няма да се разпознаят и трябва да пишеш пълни пътища.

## Част 1. Developer token (започни оттук - чака одобрение)

Developer token-ът е ключът, който казва на Google „този софтуер има право да говори с
Ads API". Издава се на MCC акаунт и **менюто се вижда само от manager акаунт**.

1. Влез в Google Ads с **MCC акаунта**.
2. **Tools & Settings → Setup → API Center.**
3. Ако още нямаш токен - системата ти генерира.
4. Заяви **Basic access**. Формата пита какъв софтуер строиш и за какво ще ползваш API-то.
   Отговаряй конкретно: вътрешен инструмент за управление на **собствените ти** рекламни
   акаунти, четене на отчети и правене на рутинни промени. Не описвай препродаване на данни
   към трети страни - това вкарва заявката в по-тежка проверка.
5. Копирай токена някъде на сигурно. Ще ти трябва в част 5.

**Какви са нивата**

| Ниво | Какво може | Лимит |
|---|---|---|
| Test | Само срещу test акаунти. Реалните ти акаунти връщат грешка. | - |
| Basic | Всичко, което ти трябва. | 15 000 операции на ден |
| Standard | За SaaS платформи с много клиенти. | Без практически лимит |

Basic е повече от достатъчно. Реалното потребление при активна работа с двайсетина акаунта
е стотици операции на ден, не хиляди.

**Докато чакаш одобрение** можеш да минеш през части 2-6 докрай. `npm run doctor` ще върне
`DEVELOPER_TOKEN_NOT_APPROVED` - това е очаквано и се оправя от само себе си в мига, в който
Google одобри. Нищо не се преправя.

## Част 2. Google Cloud проект и OAuth клиент

Тук се създава „приложението", през което твоят компютър се идентифицира пред Google.
Безплатно е, не иска карта, не се хоства нищо.

Влез в [Google Cloud Console](https://console.cloud.google.com) **със същия Google акаунт**.

### 2.1 Проект

Горе вляво, менюто с проектите → **New Project**. Кръсти го както искаш, например
`google-ads-mcp`. Изчакай да се създаде и се увери, че е избран в лентата горе.

### 2.2 Включи Google Ads API

**APIs & Services → Library** → потърси **Google Ads API** → **Enable**.

Ако този бутон не е натиснат, всяка заявка после връща грешка, че API-то не е активирано
за проекта.

### 2.3 OAuth consent screen

**APIs & Services → OAuth consent screen**:

1. User type: **External**. (Internal съществува само при Google Workspace организация.)
2. Попълни име на приложението и имейл за контакт - твоите.
3. Scopes: не добавяй нищо ръчно. Скриптът иска един scope и го подава сам.
4. Test users: **добави собствения си имейл**. Без това consent екранът ще откаже достъп.
5. Запази.

> **Важно за дълготрайността.** Ако приложението остане в статус **Testing**, Google
> изтрива refresh token-ите след **7 дни** и връзката спира да работи всяка седмица.
> Натисни **Publish app**. Verification не е нужна - приложението е само за твоя акаунт и
> ползва един-единствен scope. Ще видиш предупредителен екран „Google hasn't verified this
> app" при първото съгласие; минаваш през **Advanced → Go to ... (unsafe)**. Това е твоето
> собствено приложение, на твоя проект.

### 2.4 OAuth клиент

**APIs & Services → Credentials → Create credentials → OAuth client ID**:

- Application type: **Desktop app**
- Име: каквото ти е удобно

Google показва **Client ID** и **Client Secret**. Дръж прозореца отворен или ги запиши -
трябват ти в част 4.

> Защо точно „Desktop app": този тип клиент разрешава пренасочване към `http://localhost`
> на произволен порт, без да го регистрираш предварително. Скриптът вдига мъничък локален
> сървър на порт 8787 само за секундите на съгласието и го затваря веднага след това.

## Част 3. Кодът

Сложи папката `google-ads-mcp` където държиш проектите си. Оттук нататък примерите
приемат, че е в домашната ти папка.

```bash
cd ~/google-ads-mcp
npm install
```

Инсталира се една-единствена зависимост - официалното MCP SDK. Всичко останало е стандартен Node.

Провери, че кодът е здрав, преди изобщо да си пипала креденшъли:

```bash
npm test
```

Този тест не пипа мрежата. Проверява, че MCP сървърът вдига, че схемите на инструментите
са валидни и че guardrails-ите се зареждат. Трябва да мине изцяло зелен.

## Част 4. Refresh token

Access token-ите на Google живеят час. Refresh token-ът е дълготрайният ключ, с който
сървърът си вади нов access token, когато потрябва. Вади се веднъж.

```bash
cd ~/google-ads-mcp
GOOGLE_ADS_OAUTH_LOGIN_HINT=твоя-имейл@gmail.com npm run oauth
```

Какво се случва:

1. Скриптът пита за **Client ID** и **Client Secret** от част 2.4. Постави ги.
2. Отваря браузър със съгласието на Google. Ако не се отвори сам, копирай линка, който
   скриптът е отпечатал в терминала.
3. **Логваш се с акаунта, който има достъп до MCC-то.** Тук се бърка най-често.
4. Даваш съгласие. Табът показва „Готово ✓".
5. Скриптът записва `GOOGLE_ADS_CLIENT_ID`, `GOOGLE_ADS_CLIENT_SECRET` и
   `GOOGLE_ADS_REFRESH_TOKEN` в `~/.google-ads.env` с права 600.

Ако порт 8787 е зает от друго нещо:

```bash
OAUTH_PORT=9123 npm run oauth
```

## Част 5. Довърши конфига

Отвори `~/.google-ads.env` и попълни двете стойности, които скриптът не знае:

```
GOOGLE_ADS_DEVELOPER_TOKEN=токена от част 1
GOOGLE_ADS_LOGIN_CUSTOMER_ID=1234567890
```

`LOGIN_CUSTOMER_ID` е ID-то на MCC-то, **само цифри, без тирета**. Виждаш го горе вдясно
в Google Ads, изписано като `123-456-7890`.

Заключи файла:

```bash
chmod 600 ~/.google-ads.env
```

Готовият файл изглежда така:

```
GOOGLE_ADS_DEVELOPER_TOKEN=xxxxxxxxxxxxxxxxxxxxxx
GOOGLE_ADS_CLIENT_ID=xxxxxxxx.apps.googleusercontent.com
GOOGLE_ADS_CLIENT_SECRET=xxxxxxxxxxxxxxxx
GOOGLE_ADS_REFRESH_TOKEN=1//xxxxxxxxxxxxxxxxxxxx
GOOGLE_ADS_LOGIN_CUSTOMER_ID=1234567890
```

**Този файл е ключът към всичките ти рекламни акаунти.** Не влиза в git, не се праща по
имейл, не се качва никъде.

## Част 7. Вържи го към Claude Code

Една команда. Пътят трябва да е **абсолютен**:

```bash
claude mcp add google-ads -s user -- node ~/google-ads-mcp/src/index.js
```

`-s user` значи, че сървърът е достъпен от всяка папка, в която пуснеш Claude Code, не само
от една. Ако `~` не се разгъва при теб, напиши пълния път, например
`/Users/име/google-ads-mcp/src/index.js`.

Провери:

```bash
claude mcp list
```

После пусни `claude` и напиши `/mcp`. Трябва да видиш `google-ads` като connected с 18
инструмента. Ако Claude Code е бил отворен, рестартирай го.

## Част 8. Първи стъпки

### 8.1 Сложи предпазител, преди да пишеш каквото и да е

По подразбиране писането е разрешено навсякъде. Докато свикваш, ограничи го до един акаунт.
В Claude Code:

> Сложи writeAllowlist само с акаунт 2345678901.

Оттук нататък всеки опит за писане в друг акаунт се отказва от самия сървър, а не от
преценката на модела. Другите предпазители работят от първия ден:

- Увеличение на дневен бюджет над 50% на едно извикване - блокира се.
- `REMOVED` статус - иска изрично потвърждение.
- Над 500 операции в едно извикване - блокира се.

Когато си готова да работиш навсякъде: „Изчисти writeAllowlist."

### 8.2 Първи заявки

Започни с четене, за да усетиш какво връща:

> Покажи ми всички акаунти.

> Как се представи акаунт 2345678901 през последните 30 дни - разход, конверсии, CPA по кампании?

> Кои search terms през последните 14 дни са похарчили над 20 лв. без нито една конверсия?

> Какво е променяно в акаунт 2345678901 през последната седмица и от кого?

Последният въпрос вади историята от самия Google, включително ръчните промени, които някой
е направил през интерфейса.

### 8.3 Първа промяна

> Добави тези search terms като точни негативи на ниво кампания. Първо ми покажи какво ще стане.

Инструментът `mutate` по подразбиране е `validateOnly` - показва какво би направил, без да
го прави. Когато потвърдиш, промяната минава през guardrails, старата стойност се снима и
се записва в лог. Ако сгрешиш:

> Покажи последните промени и върни последната назад.

## Част 9. Когато не тръгне

| Съобщение | Какво значи | Какво се прави |
|---|---|---|
| `DEVELOPER_TOKEN_NOT_APPROVED` | Токенът е в Test ниво. | Чакаш одобрението на Basic access от част 1. Нищо не се преправя. |
| `USER_PERMISSION_DENIED` | Акаунтът, с който си дала съгласие, няма достъп до този клиентски акаунт. | Провери с кой акаунт си минала OAuth-а. За акаунти извън MCC-то пробвай `login-customer-id` да е самият customer ID. |
| `invalid_grant` при заявка | Refresh token-ът е анулиран или изтекъл. | Най-често приложението е останало в Testing (7 дни живот). Publish app, после пусни `npm run oauth` отново. |
| `npm run oauth` не връща refresh token | Вече си давала съгласие за този клиент. | Махни достъпа от [myaccount.google.com/permissions](https://myaccount.google.com/permissions) и пусни пак. |
| `EADDRINUSE` на 8787 | Портът е зает. | `OAUTH_PORT=9123 npm run oauth` |
| API-то не е активирано | Пропусната стъпка 2.2. | Enable на Google Ads API в Library. |
| Claude не вижда сървъра | Регистрацията не е минала или Claude Code е стар процес. | `claude mcp list`, после рестарт на Claude Code. |
| Липсва поле в GAQL заявка | Името на полето е сгрешено. | Питай „провери с describe_fields как се казва това поле" - вместо да гадаеш. |
| Празен резултат, без грешка | Заявката е валидна, но филтърът не хваща нищо. | Разшири периода. Данните от последните часове не са финални. |

Диагностика в две команди: `npm test` (кодът здрав ли е) и `npm run doctor` (връзката жива ли е).

## Част 10. Поддръжка

**Версия на API-то.** По подразбиране `v24`. Google издава нови версии на месечен цикъл,
всяка живее около година. Когато дойде време, смяната е един ред в `~/.google-ads.env`:

```
GOOGLE_ADS_API_VERSION=v25
```

**Къде живее какво**

```
~/google-ads-mcp/       кодът
~/.google-ads.env       креденшъли (chmod 600, никога в git)
~/.google-ads-mcp/      guardrails.json и changes.jsonl
```

`changes.jsonl` е локалната история на всичко, което инструментът е записал в акаунтите,
със снимка на старите стойности. Ако я изтриеш, губиш възможността за връщане назад на
старите промени.

**Две неща, които няма как да се върнат назад**

- `REMOVED` в Google Ads API е окончателен. Няма un-remove. Затова навсякъде, където може,
  се ползва `PAUSED`.
- Полета, които не се четат през GAQL, не могат да се снимат преди промяна. Такива промени
  влизат в лога маркирани `undoable: false`.
